# 0020. Testing and evaluation

- Status: accepted (2026-11-20, Approval 2)

## Context
The success metric and R6 must be proven, not asserted.

## Decision
vitest for core; fast-check property tests for every R6 invariant (provenance, lengths, charset, idempotence, parse→export preserves non-address data, bytes outside splices unchanged); integration tests on real Postgres; contract tests for OpenAPI and MCP; Playwright e2e for the storyboard; an accuracy eval led by a hand-labelled set of at least 150 messy addresses (labelled by the owner and reviewed), plus a synthetic set from separate generator templates reported apart, with n per country; LLM eval on recorded responses in CI and a separate live eval.

## Alternatives considered
Accuracy measured only on synthetic data generated by the same templates as the parser (circular).

## Consequences
Cost to reverse: Low. See [architecture](../architecture.md).
