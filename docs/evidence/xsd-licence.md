**Decision: fetch at build time. The XSDs are not committed.**
Decided 2026-11-24 in M0-04. Rule from the ticket: if the licence is unclear, fetch at build time.

## Consequences

- `schemas/xsd/` stays gitignored (only `.gitkeep` is tracked). `scripts/fetch-xsd.sh` downloads the three
  files from the pinned URLs in `schemas/xsd.lock.json` and verifies each by sha256.
- **Where the files come from.** iso20022.org cannot be reached from this build host, so the pinned
  URLs point to a mirror: `phoughton/pyiso20022` (MIT-licensed repository) at commit
  `22ee422418c20e09c634eee6f16cc978fde4fe88`, path `xsd/payments_initiation/pain.001/`. The commit
  pin makes the URL immutable; the sha256 pin makes the bytes immutable.
- **Why this mirror.** Its `.09` and `.12` files are identical in content to a second, independent
  mirror (`php-sepa-xml/php-sepa-xml` at commit `5958e51f`, LGPL-3.0); they differ only in line endings
  (CRLF here). The `.03` in the second mirror was re-edited with XMLSpy (an extra "edited with XMLSpy …
  by XMLdation" comment and reformatting), while this mirror's `.03` carries only the original
  generator comment. The repository's own MIT licence covers its code; it does not relicense ISO's
  schemas, which is another reason not to commit them.
- The element facts in `PROJECT.md` §1 were checked against these files (`docs/evidence/sources.json`
  ids `iso-xsd-pain-001-001-03`, `-09`, `-12`): PostalAddress24 lengths match; PostalAddress6 lacks
  BldgNm, Flr, PstBx, Room, TwnLctnNm and DstrctNm; pain.001.001.12 uses PostalAddress27 (adds CareOf
  140 and UnitNb 16; StrtNm, BldgNm, TwnNm, TwnLctnNm, DstrctNm become 140; CtrySubDvsn stays 35).

## Revisit when

- iso20022.org can be read (from another network or by the owner in a browser): record the terms
  section and wording here. If they allow redistribution, commit the files, keep the lock, and make
  `fetch-xsd.sh` verify only.
- Before M4-SUBMIT, M4-CLEANUP confirms `git ls-files schemas/xsd` still lists only `.gitkeep`.
