# Evidence

Sources for every domain fact in `PROJECT.md` §1, every pain row in `PROJECT.md` §2, and every
launch rule pack in ADR 0009. Captured by M0-04 on 2026-11-24.

| File | What |
|---|---|
| `sources.json` | the index, one entry per source |
| `xsd-licence.md` | the ISO 20022 XSD licence finding and the fetch-at-build-time decision |
| `load-spike.md` | M0-09: parse and insert cost for 20,000 rows at 1 CPU / 2 GB, and the worker limits |

The downloaded documents live in `data/raw/evidence/` (gitignored, never committed). The XSDs live
in `schemas/xsd/` (gitignored), fetched by `scripts/fetch-xsd.sh`.

## Reading `sources.json`

A JSON array. Each entry:

| Field | Meaning |
|---|---|
| `id` | stable id; rule packs (M2-06 to M2-09) cite it |
| `kind` | `schema`, `primary`, `bank_guide`, `bank_article`, `industry`, `scheme`, `association`, `fmi`, `press`, `forum`, `vendor` |
| `url` | the exact URL fetched (after redirects) |
| `title`, `publisher` | as shown by the document |
| `retrieved` | date fetched (YYYY-MM-DD) |
| `sha256` | hash of the downloaded bytes; `null` only when the fetch was blocked (see `capture`) |
| `local_file` | where the download sits locally (untracked) |
| `reproduction` | what the document says about copying, or that it says nothing |
| `supports` | keys of the facts, pain rows or packs it backs (table below) |
| `capture` | present only when the download failed: status, HTTP code, what was checked instead |

Bank guides (and the CBPR+ generic source) also carry:

| Field | Meaning |
|---|---|
| `message_versions` | message versions the document covers, in its own naming |
| `forms` | address forms it accepts: `structured`, `hybrid` |
| `effective_from` | the date it states, `YYYY-MM-DD`, or `YYYY-MM` when it states only a month, or `not_set` |
| `effective_from_stated` | the context of that date, including whether it predates Swift's 27 Aug 2026 deferral |

A date stated before 27 Aug 2026 is recorded as the guide states it and marked stale in
`effective_from_stated`. A rule pack built from such a guide treats it as historical, not as a
coming date.

```bash
jq -r '[.[]|select(.sha256)|.supports[]]|unique[]' docs/evidence/sources.json
```

## Rules

1. **Guide text is never copied.** Rules are encoded in our own words and structure; sources are
   cited by `id`, URL and retrieval date. Short attributed quotes appear only in `PROJECT.md` pain
   evidence and in `effective_from_stated`. Some documents forbid reproduction outright (Bank of
   Ireland: "may not be reproduced or further distributed"); several are "All rights reserved"
   (ZKB; the ING guide, generated by Swift MyStandards). No downloaded document is committed.
2. **Date wording.** Swift's cutover date is deferred and the new one is not set. Write it that way:
   "deferred on 27 Aug 2026; new date not set (Swift expects to announce it by December 2026)". A
   date a bank guide states is written as "stated by <bank> on <date>", never as a coming deadline.
   Never present a Swift date as imminent. Results say "checked against `<pack>@<version>`".
3. **Re-check before use.** Pages change. Before a pack ships (M2-07 to M2-09), re-download its
   source, compare the hash, and update `retrieved`/`sha256` (and the pack) if it changed.
4. **Blocked sources.** swift.com and kyriba.com answer HTTP 403 to automated fetches. Do not work
   around a bot wall. An entry without a hash has a `capture` note; a browser save by the owner,
   placed at `local_file`'s path and hashed, fills it in (done for Kyriba on 2026-11-24, P-40).
